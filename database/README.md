# Database workflow

PostgreSQL owns the durable data. Alembic revisions in `../backend/alembic/versions` are the source of truth for schema changes; SQLAlchemy models live in `../backend/app/models`. The application never asks the user to edit tables manually.

From the MemoryCare project root, activate the backend virtual environment and set `DATABASE_URL` in `backend/.env`, then run:

```powershell
Set-Location .\backend
..\.venv\Scripts\Activate.ps1
alembic upgrade head
alembic revision --autogenerate -m "describe the schema change"
alembic downgrade -1
```

Review autogenerated migration scripts before committing them. `alembic downgrade -1` rolls back one revision; it can remove data when that revision drops columns/tables. Back up any non-demo database first.
